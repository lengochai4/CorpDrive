Broken Access Control — Ngôi Vương Nguy Hiểm

IDOR xảy ra khi ứng dụng dùng trực tiếp định danh do người dùng gửi lên (file_id, user_id) để truy xuất tài nguyên mà không kiểm tra quyền sở hữu.

3 Lý do cốt lõi khiến IDOR giữ Top 1:

1. Tàng hình trước WAF & IDS

Request HTTP hoàn toàn hợp lệ về cú pháp (chỉ đổi số 1 → 3), không chứa ký tự đặc biệt hay chữ ký tấn công để tường lửa chặn.

2. Rào cản kỹ thuật bằng 0

Không cần exploit phức tạp hay công cụ chuyên sâu — chỉ cần trình duyệt web hoặc nhấn F12 là có thể khai thác ngay.

3. Thiệt hại diện rộng (Mass Exposure)

Dễ dàng tự động hóa vòng lặp để hút cạn toàn bộ CSDL người dùng, hồ sơ tài chính, tài liệu mật hoặc chiếm quyền tài khoản.

Phân tích Mã nguồn (White-box Analysis)

IDOR — Soi Chiếu Dòng Code Gây Lỗi (Python Flask)

Nhầm lẫn kinh điển của Lập trình viên

Authentication (Đã kiểm tra)

Xác nhận "Bạn là ai?" — User Hải đã đăng nhập hợp lệ và có Cookie Session.

Object-Level Authorization (BỊ BỎ QUA)

Không kiểm tra "User Hải có quyền truy cập đối tượng ID=2 / File ID=3 hay không?"

Luồng thực thi lỗi trong hệ thống
1 Session: user_id = 1 | Body: user_id = 2
2 SQL chỉ lọc WHERE id = 2 (bỏ qua Session!)
3 Trả nguyên JSON hồ sơ của nạn nhân #2!
app.py Python • Flask API
VULNERABLE CODE
1. API Xem Hồ Sơ (/api/profile)
1@app.route('/api/profile', methods=['POST'])
2def get_profile():
3target_id = request.json.get('user_id')
4# [LỖ HỔNG IDOR]: Tin tưởng trực tiếp ID từ client gửi lên,
5# thiếu bước kiểm tra đối chiếu với session['user_id']!
6 user = db.execute("SELECT * FROM users WHERE id = ?", (target_id,)).fetchone()
7return jsonify(user)

Điểm chết tại dòng 6: "Chỉ kiểm tra Authentication (đã đăng nhập), bỏ qua Object-Level Authorization (quyền sở hữu đối tượng)".

2. Tương tự tại API Tải Tài Liệu (/drive/download)

IDOR — Các Kịch Bản Tấn Công Thực Tế & Càn Quét Hàng Loạt

1 Thao túng tham số URL (GET) GET

Thay đổi trực tiếp số ID tuần tự trên thanh địa chỉ để xem trộm hóa đơn, bảng lương, hợp đồng nội bộ của người dùng khác.

GET /drive/download?file_id=3
2 Thao túng JSON Body (POST/PUT) POST / PUT

Chặn gói tin API, sửa user_id để đọc trộm hồ sơ cá nhân hoặc cập nhật email khôi phục → Account Takeover.

PUT /api/user/update → {"user_id": 2, "email": "hacker@evil.io"}

Dùng Burp Suite Intruder cấu hình Payload Numbers (1 → 30) tự động bắn hàng loạt request để hút sạch toàn bộ CSDL trong vài giây.

Secure Coding & Mitigation

IDOR — Đối Chiếu Code Lỗi & Giải Pháp Phòng Thủ Chuẩn

BEFORE — Code Lỗi (Vulnerable)
Thiếu kiểm tra chủ sở hữu
@app.route('/drive/download')
def download_file():
file_id = request.args.get('file_id') # Số tự tăng: 1, 2, 3
row = db.execute("SELECT * FROM files WHERE id = ?", (file_id,)).fetchone()
return send_file(row['path'])
Tin tưởng mù quáng vào tham số Client → Dễ dàng đoán ID & tải trộm.
AFTER — Code An Toàn (Secure)
Complete Mediation + UUIDv4
@app.route('/drive/download')
def download_file():
file_uuid = request.args.get('uuid')
owner_id = session['user_id'] # Lấy từ Session Server!
row = db.execute("SELECT * FROM files WHERE uuid = ? AND owner_id = ?", (file_uuid, owner_id)).fetchone()
if not row:
audit_log.warning(f"IDOR blocked: user={owner_id}")
return abort(403) # Forbidden
return send_file(row['path'])

1. Complete Mediation

Mọi truy vấn đều ràng buộc quyền sở hữu từ Session phía Server: WHERE id = ? AND owner_id = session['user_id'].

2. Dùng UUIDv4 ngẫu nhiên

Thay ID tự tăng 1, 2, 3 bằng UUIDv4 (550e8400-e29b...) giúp chống càn quét tự động (Defense-in-Depth).

3. Audit Log & 403 Forbidden

Chặn ngay bằng mã 403 Forbidden và ghi Security Audit Log để SOC/SIEM phát hiện sớm hành vi dò quét.

Injection — Chèn Lệnh Hệ Điều Hành

Phát sinh khi ứng dụng ghép trực tiếp dữ liệu người dùng chưa lọc vào chuỗi lệnh gửi cho OS Shell (cmd.exe, /bin/sh), cho phép kẻ tấn công thực thi lệnh tùy ý trên máy chủ.

RCE — Remote Code Execution

Kích hoạt trình thông dịch Shell (cmd.exe / sh) phân tích ký tự nối lệnh.

1 Classic / In-band Injection

TIME / OOB DNS

Defense-in-Depth & Secure Coding

Command Injection — Đối Chiếu Code Lỗi & Code An Toàn

Vulnerable Code (Đỏ)
Nối chuỗi + shell=True
def ping_host():
host = request.json.get('host')
# Không kiểm tra định dạng host!
subprocess.check_output(f"ping -n 2 {host}", shell=True)
OS Shell thông dịch mọi ký tự && ; | thành lệnh hệ điều hành mới.
Secure Code (Xanh lá)
Allowlist + shell=False
# 1. Allowlist Validation (Chỉ chấp nhận IP/Hostname chuẩn)
if not re.match(r'^[a-zA-Z0-9.-]{1,253}$', host):
    abort(400)
# 2. Tắt shell=False và truyền tham số dạng mảng tách biệt
subprocess.run(["ping", "-n", "2", host], shell=False)
OS gọi thẳng binary ping; chuỗi host chỉ là tham số thuần, vô hiệu hóa hoàn toàn metacharacters.

1. Tắt Shell (shell=False)

Không gọi trình thông dịch Shell. Truyền đối số dạng mảng tách biệt (hoặc ưu tiên dùng thư viện native thay vì gọi lệnh OS).

2. Allowlist Validation phía Server

Dùng Danh sách trắng (Allowlist) kiểm tra chặt kiểu dữ liệu (IP/Domain). Không dùng Blacklist vì rất dễ bị qua mặt (bypass).

3. Nguyên tắc Least Privilege

Tuyệt đối không chạy Web Server bằng quyền root / Administrator. Cách ly tiến trình bằng tài khoản đặc quyền tối thiểu / Container.
